1. STAGE 2 OBJECTIVES & SCOPE
===============================================================================

The primary goal of Stage 2 is to execute the retrieval arm of Phase 1 across all 300 SciFact test queries, compute retrieval metrics (Recall@k, MRR, nDCG@k, P@1) and search latency for 3 candidate generation arms, and verify all metric implementations against reference unit tests before proceeding to reranking (Stage 3).

Key Deliverables:
- Candidate Retrieval: Retrieve top-50 documents per query for 3 arms:
  1. BM25 (Sparse lexical baseline)
  2. Dense (BAAI/bge-base-en-v1.5 bi-encoder)
  3. RRF Hybrid (Reciprocal Rank Fusion of BM25 + Dense)
- Mandatory Chunk-to-Doc Collapse: Collapse chunk-level FAISS vectors to document level using max score aggregation prior to metric evaluation and RRF fusion.
- Hand-written Metrics Module: Implement pure-Python metric functions for Recall@k, MRR, nDCG@k, and P@1.
- Unit Test Verification: Verify hand-written metrics against reference repo B's pinned canary dataset (Recall@5 = 0.750, MRR = 0.625, nDCG@5 = 0.627) and cross-validate against ranx / pytrec_eval.
- Output Artifacts: Persist query candidate runs and evaluation summary JSON files in `artifacts/runs/`.

===============================================================================
2. TECHNICAL ARCHITECTURE & DATA FLOW
===============================================================================

Inputs:
- `artifacts/index/faiss.index`: Dense FAISS IndexFlatIP (5,661 unit vectors, dim 768)
- `artifacts/index/bm25.pkl`: Serialized rank_bm25.BM25Okapi instance (5,183 docs)
- `artifacts/index/docmap.json`: Unit ordinal <-> docid mapping & chunking policy
- `artifacts/index/index_meta.json`: Stage 1 indexing metadata
- BEIR SciFact test dataset (`corpus`, `queries`, `qrels`) loaded via `src/common.py`

Retrieval Pipeline (per query):

1. BM25 Arm:
   - Tokenize query string using `str.lower().split()`.
   - Score all 5,183 documents with `bm25.get_scores()`.
   - Select top 50 documents sorted by BM25 score descending.

2. Dense Arm (bge-base-en-v1.5):
   - Embed 300 test queries in batch using GPU fp16 with SDPA attention.
   - Prepend `BGE_QUERY_INSTRUCTION` ("Represent this sentence for searching relevant passages: ").
   - Search FAISS `IndexFlatIP` for top-200 unit ordinals per query.
   - Collapse unit ordinals to `docid` using max score aggregation (`docmap.json`).
   - Select top 50 unique documents sorted by max chunk cosine score descending.

3. RRF Hybrid Arm:
   - Perform Reciprocal Rank Fusion on doc-level rank lists from BM25 top-50 and collapsed Dense top-50:
     RRF_score(doc_id) = 1.0 / (60 + rank_bm25(doc_id)) + 1.0 / (60 + rank_dense(doc_id))
   - Rank documents by RRF_score descending to select top-50 hybrid documents.

Outputs (`artifacts/runs/`):
- `retrieval_bm25.json`: Candidate list & timings for BM25 arm.
- `retrieval_dense.json`: Candidate list & timings for Dense arm.
- `retrieval_rrf.json`: Candidate list & timings for RRF Hybrid arm.
- `stage2_retrieval_metrics.json`: Final Phase 1 quality-vs-latency comparison table.

3. METRIC MATHEMATICS & IMPLEMENTATION SPECIFICATION
===============================================================================

All metrics will be implemented from first principles in `src/metrics.py` (or integrated helper) and verified against `pytrec_eval` / `ranx`.

Mathematical Definitions:

1. Recall@k:
   Recall@k(q) = |{retrieved top-k docs} ∩ {gold relevant docs for q}| / |{gold relevant docs for q}|

2. MRR (Mean Reciprocal Rank):
   MRR(q) = 1 / rank(first relevant doc in retrieved list)  [or 0.0 if no relevant doc retrieved]
   MRR = mean over all queries.

3. nDCG@k (Normalized Discounted Cumulative Gain):
   DCG@k(q) = Σ_{i=1}^k (2^{rel_i} - 1) / log2(i + 1)
   IDCG@k(q) = DCG@k under ideal sorting of gold relevant docs.
   nDCG@k(q) = DCG@k(q) / IDCG@k(q)
   (For SciFact binary relevance, rel_i ∈ {0, 1}, so 2^{rel_i} - 1 = rel_i).

4. Precision@1 (P@1):
   P@1(q) = 1.0 if top-1 document is relevant else 0.0.
