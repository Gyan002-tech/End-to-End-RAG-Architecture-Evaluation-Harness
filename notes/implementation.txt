===============================================================================
1. STAGE 4 OBJECTIVES & SCOPE
===============================================================================

Stage 4 begins Phase 2 (Generation & Faithfulness Scoring) of the RAG evaluation harness.
It runs local answer generation for the 4 surviving Pareto frontier configurations identified in Stage 3:
  1. `Dense (bge-base) -> none` (Speed Champion: 3.19 ms, 0.7407 nDCG@10)
  2. `Dense -> bge-v2-m3` (Lightweight Rerank Knee: 1,831.80 ms, 0.7420 nDCG@10)
  3. `RRF Hybrid -> bge-v2-gemma` (Balanced Rerank Knee: 6,256.78 ms, 0.7796 nDCG@10)
  4. `Dense -> bge-v2-gemma` (Quality Champion: 6,376.81 ms, 0.7844 nDCG@10)

Key Deliverables:
- Local Generator Integration: Adapt `src/generate.py` from Reference Repo A (`tim-ponomarev/hybrid-rag`), replacing external API calls with local `Qwen/Qwen2.5-1.5B-Instruct` via HuggingFace `transformers`.
- Citation-Aware RAG Prompting: Format top-5 retrieved context passages with explicit `[Document {doc_id}]: {text}` tags and instruct Qwen2.5-1.5B to answer using ONLY the context with inline citations.
- Deterministic Answer Generation: Generate answers for all 300 test queries across all 4 Pareto survivor runs using greedy decoding (`temperature=0.0`, `max_new_tokens=256`).
- Latency & Output Persistence: Measure answer generation latency per query and save generated runs to `artifacts/runs/gen_*.json`.
- GPU VRAM Cleanup: Unload Qwen2.5-1.5B cleanly from GPU VRAM (`del generator; torch.cuda.empty_cache(); gc.collect()`) to unblock Stage 5 (Local Qwen2.5-7B Faithfulness Judge).

===============================================================================
2. GENERATOR MODEL & GPU MEMORY GUARDRAILS
===============================================================================

Model: `Qwen/Qwen2.5-1.5B-Instruct`
- Type: Causal LLM Generator (1.5 billion parameters).
- Precision: `fp16` on CUDA with PyTorch SDPA (`attn_implementation="sdpa"`).
- VRAM Footprint: ~3.0 GiB static weight VRAM.
- Why 1.5B? Small, fast local instruction-tuned LLM that executes in milliseconds per query on a T4 GPU without exceeding memory limits.

VRAM Guardrails & Staged Residency:
- Generator runs strictly AFTER Stage 3 rerankers are unloaded.
- Generator unloads completely from VRAM BEFORE Stage 5 (`Qwen2.5-7B-Instruct` judge) loads.
- Strictly single-model residency enforced at all times.

===============================================================================
4. STEP-BY-STEP IMPLEMENTATION PLAN
===============================================================================

Step 1: Generator Module (`src/generator.py`)
- Implement `LocalGenerator` class wrapping `Qwen/Qwen2.5-1.5B-Instruct` via HuggingFace `AutoModelForCausalLM` and `AutoTokenizer`.
- Include SDPA attention, `torch.float16` precision, greedy decoding (`temperature=0.0`, `do_sample=False`, `max_new_tokens=256`).
- Define citation prompt template formatting top-K (top-5) context documents:
  ```
  Context Documents:
  [Document 101]: Abstract text...
  [Document 202]: Abstract text...

  Query: Scientific claim query text...
  Task: Answer the query based ONLY on the provided context documents. Cite source documents inline as [Document doc_id].
  ```

Step 2: Stage 4 Runner (`src/04_generate.py`)
- Load SciFact dataset (`queries`), `docmap.json`, and the 4 Pareto survivor run JSONs.
- Instantiate `LocalGenerator` on CUDA GPU.
- For each survivor configuration:
  - For each of the 300 test queries:
    - Extract top-5 retrieved context documents.
    - Format citation prompt -> run Qwen2.5-1.5B generation -> measure generation time (ms).
    - Store generated answer string, cited docids, and generation latency.
  - Save run JSON to `artifacts/runs/gen_{config_slug}.json`.
- Compute generation summary metrics (mean generation latency ms/query, answer word counts) and save `stage4_generation_summary.json`.
- Unload `LocalGenerator` from GPU VRAM (`unload_model()`).

Step 3: Stage 4 Verification Script (`src/verify_stage4.py`)
- Cold reload all 4 generated answer JSONs and `stage4_generation_summary.json`.
- Check answer completeness (300 queries per survivor run, non-empty answer strings).
- Check citation integrity (presence of `[Document ...]` tags in generated answers).
- Display summary table of answer generation times and output sizes.
