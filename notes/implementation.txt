===============================================================================
1. STAGE 5 OBJECTIVES & SCOPE
===============================================================================

Stage 5 completes Phase 2 (Generation & Faithfulness Scoring) of the RAG evaluation harness.
It runs local LLM-as-a-Judge evaluation using `Qwen/Qwen2.5-7B-Instruct` across all 1,200 generated RAG answers (300 queries x 4 Pareto survivor runs):
  1. `Dense (bge-base) -> none` (Speed Champion)
  2. `Dense -> bge-v2-m3` (Lightweight Rerank Knee)
  3. `RRF Hybrid -> bge-v2-gemma` (Balanced Rerank Knee)
  4. `Dense -> bge-v2-gemma` (Quality Champion)

Key Deliverables:
- Local LLM Judge Integration: Adapt `src/judge.py` from Reference Repo A (`tim-ponomarev/hybrid-rag`), replacing OpenAI `gpt-4o-mini` API calls with local `Qwen/Qwen2.5-7B-Instruct` (with automatic 4-bit `bitsandbytes` fallback for T4 16GB VRAM safety).
- Faithfulness Rubric Scoring: Deconstruct generated RAG answers into atomic claims, check whether each claim is logically supported by retrieved context passages, and compute:
  Faithfulness = Supported Claims / Total Claims Made in Answer
- Per-Query JSON Judgment: Return structured judgment per query containing `faithfulness_score`, `total_claims`, `supported_claims`, and list of `unsupported_claims`.
- Final Phase 2 Pareto Matrix: Assemble the final Phase 2 summary table combining nDCG@10, End-to-End Latency, and Faithfulness Score across all 4 survivor configurations.

===============================================================================
2. JUDGE MODEL & GPU MEMORY GUARDRAILS
===============================================================================

Model: `Qwen/Qwen2.5-7B-Instruct`
- Type: Causal LLM Judge (7.0 billion parameters).
- Size / VRAM: ~14.0 GiB (fp16 on CUDA). If VRAM exceeds bounds on T4 (14.56 GiB ceiling), automatically fall back to 4-bit `bitsandbytes` quantization (`load_in_4bit=True`).
- Why 7B? A larger, highly capable instruction-tuned LLM required for complex factual claim verification and logical deduction without paying OpenAI API costs.

VRAM Guardrails:
- `Qwen2.5-1.5B-Instruct` generator was fully unloaded in Stage 4.
- Single-model VRAM residency strictly maintained.
- `Qwen2.5-7B-Instruct` unloads completely from GPU VRAM after Stage 5.

===============================================================================
4. STEP-BY-STEP IMPLEMENTATION PLAN
===============================================================================

Step 1: Judge Module (`src/judge.py`)
- Implement `LocalJudge` class wrapping `Qwen/Qwen2.5-7B-Instruct` with automatic 4-bit bitsandbytes fallback and VRAM cleanup helper (`unload_model()`).
- Implement faithfulness evaluation prompt constructing JSON output schema:
  ```json
  {
    "faithfulness_score": 1.0,
    "total_claims": 3,
    "supported_claims": 3,
    "unsupported_claims": []
  }
  ```

Step 2: Stage 5 Runner (`src/05_judge.py`)
- Load `docmap.json` and the 4 generated answer JSONs from Stage 4.
- Instantiate `LocalJudge` on CUDA GPU.
- For each survivor configuration:
  - For each of the 300 test queries:
    - Extract generated answer and top-5 retrieved context texts.
    - Run `LocalJudge` evaluation -> parse JSON judgment -> measure per-query judge latency.
    - Store judgment output per query.
  - Save judgment JSON to `artifacts/runs/judge_{config_slug}.json` immediately after each survivor completes (incremental persistence).
- Compute overall mean faithfulness scores and save `artifacts/runs/stage5_faithfulness_summary.json`.
- Unload `LocalJudge` from GPU VRAM.

Step 3: Stage 5 Verification Script (`src/verify_stage5.py`)
- Cold reload all 4 judgment JSONs and `stage5_faithfulness_summary.json`.
- Validate completeness (300 judgments per run, valid faithfulness scores in [0.0, 1.0]).
- Render the **Final Phase 2 Pareto Survivor Matrix**:
  Config | Retrieval nDCG@10 | Total Query Latency (ms) | Faithfulness Score
- Confirm project completion.
